# Code Review Guidelines

## Approvals
Every pull request needs one approval. Changes to payment, authentication or database migration code need two approvals, one of them from a code owner.

## Size
Keep pull requests under 400 changed lines where possible. Large refactors should be split into a mechanical change and a behavioral change.

## Turnaround
Reviewers should respond within one business day. If a review is blocking a release train, ping the reviewer directly in the #reviews channel.
